FIT /fit Command Cleanup

Recommendations for removing redundant human-facing commands while preserving their useful behavior inside existing commands.

Suggestions only No code changes Human /fit surface
Guiding principle: keep one obvious command per job. Remove commands that only preview, duplicate, or alias behavior that another command can already provide.

Recommended removals

Remove

/fit current

Fold this into /fit show with no query. That keeps the “show what I’m working on” workflow while deleting a separate command.

Remove

/fit resume

/fit work already acts on the current in_progress ticket. Clarify that behavior instead of maintaining a second command.

Remove

/fit slug

This is a development preview with little human value now that ticket names are derived automatically from the first seven words.

What must change to preserve behavior

Change Reason Risk
Make the query optional on /fit show [query]. Preserves the current-ticket view after removing /fit current. Low — one branch in the show handler.
Document /fit work as “work on current, or promote then work.” Makes the removal of /fit resume obvious and safe. Low — help and README wording only.
Keep the [review] flag on /fit work and /fit start. Ensures removing /fit resume does not remove review-mode access. Low — already supported.
Remove /fit slug from help and docs. No replacement is needed; automatic naming handles the normal workflow. Low — documentation cleanup.

Alias cleanup

Command aliases are useful when they are short and obvious. These add surface area without much benefit:

  • show-current, sc — removed with /fit current.
  • code, vscode — keep /fit open as the single name.

Keep useful short aliases: mv, pri, add, w, and r.

Net result

Three fewer commands: /fit current, /fit resume, and /fit slug. No workflow is lost. The main behavior change is that /fit show becomes useful without an argument.

Suggested order of work: update the command handlers first, then help text, then README tables and examples. This is a human-facing cleanup only; the agent fit_* tools are out of scope and should be reviewed in a separate ticket.
